## 1. 模块定位

推荐模块是 MindPal 对话系统的"主动关怀"组件。在用户表达负面情绪或求助意向时，推荐模块负责从内容库中选取最匹配的心理自助资源（文章、冥想音频、练习工具等），以 soft（自然语言建议）或 hard（显式推送卡片）的方式呈现给用户。

推荐不是每轮对话都触发。它经过**两层控制**：

1. **门控层 (RecommendGate)** — 判断当前轮"是否适合推荐"以及"用什么方式推荐"
2. **排序层 (ContentRecommender)** — 判断"推荐哪几条内容"以及"按什么顺序"

## 3. 核心数据流

### 3.1 请求生命周期中的推荐位置

```
用户输入
  │
  ├─ 加载会话 → conversation_summary
  ├─ 情绪分析 → emotion_state
  ├─ 加载画像 → user_profile
  ├─ 风险评估 → risk_state
  │
  ├─ ★ recommend_gate.decide(emotion, risk, summary, profile)
  │     → { should_recommend, recommend_type, score, reason_codes }
  │
  ├─ 路由决策
  │   ├─ Level 3 / 第三方求助 → 危机响应, 推荐绕过
  │   ├─ Level 2 → 专用支持回复, gate 返回 safety_only
  │   └─ 正常 → LLM ReAct Agent（提示中注入 gate 决策）
  │
  ├─ LLM Agent 循环（最多 5 轮）
  │   ├─ recommend_content 工具可用性受 gate 控制
  │   │   ├─ hard → 允许调用
  │   │   ├─ soft → 跳过工具（返回 recommend_gate_soft）
  │   │   └─ none → 跳过工具
  │   └─ 若 gate=hard 但 LLM 未使用工具 → 编排器自动回退调用
  │
  ├─ 输出安全检查 → 可覆盖推荐内容
  └─ 持久化 → mark_recommendation() 写入推荐事件
```

### 3.2 推荐引擎内部流程

```
recommend_content()
  │
  ├─ normalize_user_profile()           # 补充画像默认值
  ├─ check risk_level == LEVEL_3 → 返回空
  │
  ├─ _retrieve_candidates()
  │   ├─ _build_query_variants()        # 5 路查询变体
  │   │   ├─ raw_input (weight 1.0)
  │   │   ├─ emotion_enhanced (0.8)
  │   │   ├─ stress_source (0.7)
  │   │   ├─ intent_enhanced (0.65)
  │   │   └─ long_memory (0.55)
  │   ├─ hybrid_retriever.retrieve()    # 每路分别检索
  │   │   ├─ bm25_retriever.retrieve()
  │   │   ├─ vector_retriever.retrieve()
  │   │   └─ RRF 融合
  │   ├─ 加权聚合所有变体结果
  │   └─ 兜底: content_db.search_content()
  │
  ├─ _rank_candidates()                 # 规则个性化排序
  │   12 维归一化子分，加权合成 final_score
  │
  ├─ _ai_based_recommendation() (可选)  # LLM 重排
  │   ├─ 成功 → 使用 LLM 排序
  │   └─ 失败 → 回退规则结果
  │
  ├─ _generate_rationale()              # 推荐理由
  └─ _calculate_match_scores()          # 匹配度分（display only）
```

## 4. RecommendGate: 推荐门控

### 4.1 加权公式

```
recommend_score = 
    0.30 × emotion_intensity
  + 0.23 × risk_score
  + 0.23 × intent_score
  + 0.14 × trend_score
  + 0.10 × preference_score
  - cooldown_penalty
```

### 4.2 因子映射

| 因子 | 来源 | 值映射 |
|------|------|--------|
| `emotion_intensity` | 情绪分析器 | 0~1 原始值 |
| `risk_score` | 风险评估 | LEVEL_0=0.0, LEVEL_1=0.4, LEVEL_2=0.75, LEVEL_3=1.0 |
| `intent_score` | 用户意图分类 | sharing=0.0, seeking_relief=0.45, planning=0.55, seeking_help=0.75 |
| `trend_score` | 情绪趋势 | negative_trend=0.35, 否则 0 |
| `preference_score` | 画像匹配 | 风格匹配 +0.45, 压力来源 +0.35, 拒绝 -0.25, 上限 [-0.3, 1.0] |
| `cooldown_penalty` | 冷却机制 | distance≤1 → -0.35, distance=2 → -0.18, ≥3 → 0 |

### 4.3 决策矩阵

| 条件 | `should_recommend` | `recommend_type` | 说明 |
|------|-------------------|------------------|------|
| Level 3 | `False` | `none` | 安全路由覆盖，不走推荐 |
| Level 2 | `False` | `safety_only` | 仅推荐 soft+beginner+≤10min 内容 |
| score ≥ hard_threshold(0.58) 且满足意图/情绪条件 | `True` | `hard` | 通用硬推 |
| **intent=seeking_help 且 score ≥ help_intent_hard_threshold(0.38)** **(v4.5)** | **`True`** | **`hard`** | **求助意图专用低硬阈值** |
| score ≥ soft_threshold(0.20) | `True` | `soft` | LLM 仅做自然语言建议 |
| score < 0.20 | `False` | `none` | 不做推荐 |

### 4.4 冷却机制

- `cooldown_penalty`: 基于对话轮次距离，上次推荐越近惩罚越大
  - **soft 推荐**: distance≤1 → -0.35, distance=2 → -0.18（可通过 `.env` 调参）
  - **hard 推荐**: distance≤1 → -0.50, distance=2 → -0.25（硬推更 intensive，冷却更强）
- `dedup_penalty`（排序层）: `recent_recommendation_item_ids` 中的内容额外降权 -0.6（加权后 -0.018）
- `reason_codes`: `cooldown_penalty` / `has_recent_recommendations`

### 4.5 用户拒绝检测 (v4.5)

对话文本中检测到用户拒绝推荐意图时，自动降低推荐倾向：

- **检测方式**: 关键词正则匹配（"不用了""不需要""没兴趣"等 12 种模式），定义在 `backend/rejection_detector.py`
- **注入时机**: `agent_orchestrator.py` 中每轮对话后检测，注入到 `conversation_summary.has_rejected_recommendation`
- **门控影响**: `_calculate_preference_score()` 检测到拒绝信号时额外 -0.25，同时产生 `user_rejected_recommendation` reason code

### 4.5 可配置项（config.py → .env）

所有权重和阈值可通过环境变量覆盖：

```
RECOMMEND_GATE_EMOTION_WEIGHT=0.30
RECOMMEND_GATE_RISK_WEIGHT=0.23
RECOMMEND_GATE_INTENT_WEIGHT=0.23
RECOMMEND_GATE_TREND_WEIGHT=0.14
RECOMMEND_GATE_PREFERENCE_WEIGHT=0.10
RECOMMEND_GATE_HARD_THRESHOLD=0.58
RECOMMEND_GATE_SOFT_THRESHOLD=0.22
```

## 5. ContentRecommender: 内容推荐引擎

### 5.1 排序公式

重构后（v4.3）采用**归一化子分 + 加权合成**，不再遗留中间 `score` 累加：

```
final_score = 
    0.25 × retrieval_score
  + 0.18 × emotion_match_score
  + 0.12 × keyword_match_score
  + 0.10 × concern_match_score
  + 0.07 × stage_match_score
  + 0.10 × risk_match_score
  + 0.10 × preference_score        # _preference_match + _calc_profile_boost + _calc_duration_match
  + 0.10 × actionability
  - 0.05 × repetition_penalty
  - 0.03 × dedup_penalty            # 内容去重
  + 0.02 × popularity_component
  + 0.02 × priority
```

### 5.2 各子分计算方法

| 子分 | 方法 | 说明 |
|------|------|------|
| `retrieval_score` | `_normalize_retrieval_score()` | BM25+向量混合检索分，归一化到 0~1 |
| `emotion_match_score` | `_calc_emotion_match()` | 精确匹配 1.0，权重映射匹配 0.8，无匹配 0.0 |
| `keyword_match_score` | `_calc_keyword_match()` | 每命中关键词 +0.33，上限 1.0 |
| `concern_match_score` | `_calc_concern_match()` | 任意关切点命中 tag/category 得 1.0 |
| `stage_match_score` | `_calc_stage_match()` | 难度与对话阶段适配得 1.0 |
| `risk_match_score` | `_calc_risk_match()` | 风险适配 1.0，禁忌 -1.0，默认 0.2 |
| `preference_score` | 三个方法合并 | 类型/类别/难度 + profile_boost + duration_match，上限 1.0 |
| `repetition_penalty` | 0.4 | 近期有推荐记录时 |
| `dedup_penalty` | 0.6 | 内容在过去 5 轮出现过 |
| `popularity_component` | `min(popularity * 0.01, 0.1)` | — |
| `priority` | item.priority | 内容优先级（0~1） |
| `actionability` | item.actionability | 内容可操作性（0~1） |

### 5.3 安全过滤

Level 2 环境下的内容过滤 (`_is_item_allowed_for_risk`):

| 条件 | Level 0/1 | Level 2 | Level 3 |
|------|-----------|---------|---------|
| 允许 | 全部 | 仅 `soft` + `beginner` + ≤10min | 无 |
| recommend_type | 任意 | 仅 `soft` | — |
| difficulty | 任意 | 仅 `beginner` 或无 | — |
| duration | 不限 | ≤10 分钟 | — |

### 5.4 情绪-内容映射

`emotion_weights` 定义了 12 种情绪到内容类和标签的映射关系，用于查询变体构建和排序匹配：

| 情绪 | 映射目标 |
|------|---------|
| 学业压力 | academic, stress_management |
| 焦虑 | relaxation, mindfulness, anxiety |
| 抑郁 | self_reflection, mood_management |
| 愤怒 | anger_management, emotional_regulation |
| 压力 | stress_management, relaxation |
| 人际矛盾 | relationship, communication |
| 困惑 | self_reflection, decision_making |
| 不确定 | future, decision_making |
| 未来迷茫 | future, career_planning |
| 自我怀疑 | self_esteem, self_reflection |
| 孤独 | relationship, social_skills |
| 失眠 | sleep, relaxation |

### 5.5 AI Rerank (可选)

- 通过 `ENABLE_RECOMMEND_AI_RERANK` 开关（默认开启）
- 将规则排序 Top-10 候选发给 DeepSeek Chat 做 LLM 精选
- 期望返回 `{"ids": ["id1", "id2", "id3"]}`
- 兼容 `content_ids` / `recommendations` 或直接列表格式
- 失败时自动回退到规则排序结果

### 5.6 推荐理由生成

`_generate_rationale()` 基于对话阶段使用不同模板，对前 2 项内容引用 `retrieval_metadata.final_score` 生成具体理由（如"匹配度达 85%"），保底使用情绪/关切点匹配。

## 6. 混合检索层

### 6.1 架构

```
hybrid_retriever.retrieve()
  ├── bm25_retriever.retrieve()    → List[(ContentItem, score)]
  └── vector_retriever.retrieve()  → List[(ContentItem, score)]
       └── RRF 融合 (k=60)         → 排序结果
```

### 6.2 BM25 实现

纯 Python 实现，无外部依赖：

- **分词**: 正则 `[一-龥]{1,4}|[a-zA-Z0-9_]+`，2-4 字中文块做 **二元组扩展**（"焦虑" → ["焦虑", "焦", "虑"]）
- **文档构建**: 拼接 title / description / category / tags / emotion_tags / type / difficulty
- **公式**: `IDF × (tf × (k1+1)) / (tf + k1 × (1-b + b × doc_len/avg_doc_len))`，k1=1.5, b=0.75

### 6.3 向量检索

轻量语义近似，无需嵌入模型：

- **分词**: 同 BM25
- **同义词扩展**: 15 组根词 → 同义词列表，覆盖全部 12 种情绪：

| 根词 | 同义词（含英文） |
|------|----------------|
| 焦虑 | 紧张, 担心, 不安, anxiety |
| 压力 | 压得喘不过气, 压力大, stress, 任务过载 |
| 学业 | 考试, 论文, 复习, 成绩, 毕业 |
| 求职 | 找工作, 面试, 实习, 职业规划 |
| 未来 | 方向, 规划, 迷茫, career |
| 睡眠 | 失眠, 睡不着, 入睡, 放松 |
| 关系 | 朋友, 室友, 对象, 沟通, 冲突 |
| 放松 | 呼吸, 冥想, 正念, relaxation |
| 抑郁 （v4.3） | 情绪低落, 沮丧, 压抑, 消沉, depression |
| 愤怒 （v4.3） | 生气, 烦躁, 恼火, 暴躁, anger |
| 人际 （v4.3） | 社交, 相处, 交往, relationship |
| 困惑 （v4.3） | 迷茫, 不解, 纠结, confusion |
| 自我怀疑（v4.3） | 不自信, 自卑, 否定自己, self_doubt |
| 孤独 （v4.3） | 孤单, 寂寞, 被孤立, loneliness |
| 失眠 （v4.3） | 睡不着, 入睡困难, 熬夜, insomnia |

- **相似度**: 稀疏向量余弦相似度

### 6.4 RRF 融合

```
RRF_score(item) = Σ 1 / (k + rank(item, result_set))
```

k=60，求和 BM25 和 Vector 两路结果的倒排排名。融合结果按总分降序。

## 7. 内容数据库

### 7.1 概况

- 存储方式: JSON 文件 (`data/content_db.json`)
- 内容数量: **27 条**（v4.3 从 8 条扩展）
- 管理类: `ContentDatabase`（单例）

### 7.2 内容模型 (`ContentItem`)

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | str | 唯一标识 |
| `title` | str | 标题 |
| `type` | str | article / audio / video / exercise / tool |
| `category` | str | 分类（academic / relaxation / mindfulness / …） |
| `description` | str | 简述 |
| `content` | Optional[str] | 正文 |
| `url` | Optional[str] | 内容链接 |
| `duration_minutes` | Optional[int] | 时长（音频/视频） |
| `tags` | List[str] | 标签 |
| `emotion_tags` | List[str] | 适配情绪 |
| `risk_levels` | List[str] | 适配风险等级 |
| `contraindications` | List[str] | 禁忌症 |
| `recommend_type` | str | soft / hard |
| `priority` | float | 优先级 |
| `source` | Optional[str] | 来源 |
| `actionability` | float | 可操作性（0~1） |
| `retrieval_metadata` | Optional[Dict] | 排序元数据（运行期填充） |
| `difficulty` | Optional[str] | beginner / intermediate / advanced |
| `popularity` | int | 热度 |
| `created_at` | datetime | 创建时间 |

### 7.3 内容分布

| 维度 | 分布 |
|------|------|
| **类型** | article 13 / audio 7 / exercise 3 / tool 3 / video 1 |
| **难度** | beginner 18 / intermediate 8 / advanced 1 |
| **风险** | low 27 / medium 27 / high 2 |
| **情绪覆盖** | 12 种全部覆盖（焦虑 20 条、压力 13 条、抑郁 8 条……） |

### 7.4 模式升级

`_upgrade_item_schema()` 为旧版内容补充缺失字段（`risk_levels`、`contraindications`、`recommend_type` 等），确保向后兼容。特定历史 ID 有定制化默认值。

## 10. 关键决策记录

### 10.1 Score 逻辑重构 (v4.3)

**问题**: `_rank_candidates()` 内部有两套打分逻辑同时运行。中间 `score` 累加大分值（+3.0 情绪、+2.0 关键词），最终只贡献 2%（`score * 0.02`），说明早期 score 的计算几乎浪费。

**方案**: 
- 删除中间 `score` 累加，所有维度产出的子分归一化为 0~1
- `_calculate_match_scores()` 优先读取 `retrieval_metadata.final_score`，不再独立重算全部匹配逻辑
- 画像偏好相关逻辑合并为 `_preference_match_score` + `_calc_profile_boost` + `_calc_duration_match`

**调整权重**: 检索 0.35→0.25、情绪 0.20→0.18、新增 keyword 0.12、concern 0.10、stage 0.07、dedup -0.03。总和仍为 1.0。

### 10.2 同义词扩展 (v4.3)

从 8 组扩展到 15 组，确保 12 种情绪在向量检索层都有同义词覆盖。新增 `抑郁`、`愤怒`、`人际`、`困惑`、`自我怀疑`、`孤独`、`失眠` 共 7 组。

### 10.3 推荐去重 (v4.3)

`conversation_summary` 新增 `recent_recommendation_item_ids` 字段（来自最近 5 轮推荐事件），`_rank_candidates` 中对已推荐内容施加 `dedup_penalty`（-0.6，加权后 -0.018），配合 reason code 标记。

### 10.4 RecommendGate 可配置化 (v4.3)

权重和阈值从硬编码迁移至 `config.py` 的环境变量读取，支持 `.env` 覆盖调参。

### 10.5 RecommendationTrace 全链路追踪 (v4.4)

新增 `backend/recommendation_trace.py`，TraveEvent Pydantic 模型记录门控输入/输出/推荐结果/安全覆盖/性能耗时，写入 `logs/recommendation_trace.jsonl`。在 `agent_orchestrator.py` 中嵌入 3 处 trace 调用点。

数据库 `recommendation_events` 表新增 5 个字段（gate_score, gate_threshold, reason_codes, cooldown_remaining, safety_overridden）。

### 10.6 评测数据集与框架 (v4.4)

构建 96 条标注评测用例（12 场景、8 类指标），评测框架 `agent_test_data/eval_recommend_gate.py` 支持 Gate Accuracy / Mode Accuracy / Hard Precision / Soft Recall / Safety Lock Rate 等指标自动化计算。

### 10.7 门控校准与二级硬阈值 (v4.5)

基于评测基线发现两个核心问题：
- **Hard Precision = 0%**：13 条求助案例全部未触发 hard，得分 0.40-0.55 < 阈值 0.58
- **Soft Recall = 68.42%**：18 条 soft 案例被标为 none

**方案**：
- soft_threshold 从 0.22 降至 0.20（保持 0.11 安全间距）
- 新增 `help_intent_hard_threshold = 0.38`：intent=seeking_help 时使用更低的硬阈值
- 冷却惩罚改为可配置，并区分 hard/soft
- 引入 `rejection_detector.py`，对话文本检测拒绝信号

**效果**：Gate Accuracy 81.25%→95.83%，Hard Precision 0%→100%，Soft Recall 68.42%→92.98%。
