## 1. 概述

MindPal Pro 的"长期记忆"在 v2.0 重构前是一组**跨文件协作**的持久化机制。经过 Phase 0-2 重构后，风险记忆已迁移到独立表，`memory_items` 已接入统一写入 Pipeline（MemoryPolicy 门控 + MemoryWriter 抽取），`MemoryStore` 支持惰性建表和 access_count 追踪。

当前系统体系：SQLite 持久化跨会话数据 + 内存字典缓存当前会话 + 多级门控写入 + 独立风险记忆表（事务安全）+ 统一记忆写入 Pipeline。

**核心文件一览：**

| 文件 | 角色 | 阶段 |
|------|------|------|
| [conversation_manager.py](../backend/conversation_manager.py) | 会话管理中枢：内存缓存 + 持久化编排 + 上下文压缩 | 原有 |
| [database.py](../backend/database.py) | SQLite 持久化层（同步 + 异步），含 v2.0 新表 DDL | 原有 + P0 |
| [risk_memory.py](../backend/risk_memory.py) | 跨会话风险记忆（v2.0）：主写入 RiskMemoryStore，JSON 兼容降级 | P1 重写 |
| [risk_memory_store.py](../backend/risk_memory_store.py) | **风险记忆独立存储**：risk_events / risk_baselines 等表的 CRUD + 事务写入 | **P0 新建** |
| [memory_store.py](../backend/memory_store.py) | **统一记忆存储**：MemoryItem CRUD + 惰性建表 + busy_timeout + access_count 追踪 | **P0 新建 + P2 升级** |

### 2.2 短时 vs 长时存储对照

| 维度 | 短时（内存） | 长时（SQLite） |
|------|-------------|---------------|
| **存储位置** | `ConversationManager.sessions` dict | 14 张 SQLite 表（含 v2.0 新增 7 张） |
| **数据范围** | 当前活跃会话（无 LRU 驱逐） | 全部历史会话（30 天 TTL） |
| **对话历史** | 最多 20 轮 (`MAX_HISTORY`) | 完整历史，过期清理 |
| **用户画像** | `session.long_term_profile` 缓存 | `user_profile` 表，无 TTL |
| **情绪事件** | — | `mood_events` 表，无 TTL |
| **风险记忆** | — | `risk_events` + `risk_baselines` + `risk_triggers` 独立表 |
| **统一记忆** | — | `memory_items` 表（含 importance / confidence / TTL） |
| **推荐反馈** | 最近 10 条 | `recommendation_feedback` 表 |
| **查询方式** | O(1) dict lookup | 每次操作新建 aiosqlite 连接 |

## 3. 七大记忆子系统

### 3.1 会话历史子系统

**数据模型：** `conversation_history` 表，每条记录包含：

| 字段 | 类型 | 说明 |
|------|------|------|
| session_id | FK→sessions.id | 所属会话 |
| turn_number | INTEGER | 轮次号 |
| user_input | TEXT | 用户输入 |
| detected_emotion | TEXT | 当前情绪标签 |
| context_emotion | TEXT | 上下文情绪 |
| confidence | REAL | 置信度 |
| ai_response | TEXT | 模型回复 |
| timestamp | TIMESTAMP | 时间戳 |

**写入流程：** `add_interaction()` → 追加到内存 session.history → 限制 20 轮 → `_schedule_persistence()` 异步写回 SQLite

**读取流程：** `get_or_create_session_async()` → 优先查内存 → 未命中则从 SQLite 加载完整 session 数据 → 组装 `_build_loaded_session_dict()`

**清理机制：** `cleanup_expired_sessions_async(days=30)` 清理 SQLite 中 `last_active` 早于截止日期的记录，同时清理内存中过期条目

### 3.2 Token 感知上下文压缩

在 `_compress_conversation_context()` 中实现：

```
阈值计算:
  soft_limit = max_tokens × 65%
  hard_limit = max_tokens × 85%

正常状态 (token < soft):
  context_quality = 1.0, compression_level = 'none'

软压缩 (soft ≤ token < hard):
  保留最近 40% token 预算 → 原始格式
  较早轮次 → 摘要格式 [emotion(src)] 用户提到: text...
  context_quality = 0.85

硬压缩 (token ≥ hard):
  保留最近 25% token 预算 → 原始格式
  较早轮次 → 摘要格式（更激进截断）
  context_quality = 0.75
```

**Token 估算：** 优先使用 `tiktoken`（按 model 获取编码器），回退 `len(text) // 4`

### 3.3 用户画像子系统

**存储结构：** `user_profile` 表，`preferences` 为 JSON 字段

```json
{
  "main_stress_sources": ["求职压力", "人际关系"],
  "preferred_support_style": "direct_actionable",
  "avoid_style": ["empty_comfort"],
  "recommendation_feedback": { "content_id_1": "accepted" },
  "risk_memory": { "@deprecated": "v2.0 后仅保留摘要，主存储迁移到 risk_events 表" },
  "profile_version": 2
}
```

**写入门控逻辑** (`_update_long_term_signals()`):

| 信号类型 | 门控条件 | 写入目标 |
|---------|---------|---------|
| 压力源 | 同一 stress_source 在最近 6 轮中出现 ≥2 次 | `main_stress_sources` |
| 支持风格 | 显式关键词匹配（如"直接告诉我怎么做"） | `preferred_support_style` |
| 意图推断 | 最近 6 轮中 planning/seeking_help 出现 ≥2 次且尚无偏好 | `preferred_support_style` |
| 回避偏好 | 匹配"不要空泛安慰"等模式 | `avoid_style` |
| 风险等级 | 每轮更新 | `risk_level` |

### 3.4 情绪历史子系统

**存储结构：** `mood_events` 表 + `emotion_timeline` 表（会话内）

**mood_events 表字段：**

| 字段 | 类型 | 说明 |
|------|------|------|
| user_id | TEXT | 用户 ID |
| session_id | TEXT | 会话 ID |
| emotion | TEXT | 情绪标签 |
| emotion_type | TEXT | 情绪类型（模式迁移补充） |
| emotion_intensity | REAL | 强度 0~1 |
| stress_source | TEXT | 压力来源 |
| user_intent | TEXT | 用户意图 |
| event_summary | TEXT | 自然语言摘要 |
| risk_level | TEXT | 关联风险等级 |
| text_snippet | TEXT | 原文片段 |
| source | TEXT | 来源（默认 conversation） |

**检索路径：**
- `MoodTrackingTool.get_recent_trend(limit=20)` — Agent 工具调用，获取趋势
- `_select_relevant_mood_events()` — 评分排序后选 top 0-3 条注入提示词

### 3.5 风险记忆子系统（v2.0）

**v2.0 变更：** 风险记忆已从 `user_profile.preferences.risk_memory` JSON blob **完全迁移到独立表**。解决了 P0 并发覆盖安全问题。

**存储结构：** 四张独立表，均为 `RiskMemoryStore` 管理

| 表名 | 内容 | 写入方式 | 并发安全 |
|------|------|---------|---------|
| `risk_events` | append-only 风险事件日志 | `add_risk_event()` | ✅ 单事务 + 行级锁 |
| `risk_baselines` | 每用户一行风险基线 | `set_baseline()` / `recompute_baseline()` | ✅ INSERT OR REPLACE |
| `risk_triggers` | 触发词频次统计 | `add_risk_trigger()` | ✅ ON CONFLICT DO UPDATE |
| `protective_factors` | 保护因素列表 | `add_protective_factor()` | ✅ 独立插入 |

**基线计算规则**（与 v6.0 算法一致）：

| 窗口 | 条件 | baseline |
|------|------|---------|
| 7 天内有 ≥1 次 Level 3 | → high |
| 7 天内有 ≥2 次 Level 2 | → high |
| 14 天内有 ≥1 次 Level 2 | → medium |
| 14 天内有 ≥3 次 Level 1 | → medium |
| 否则 | → low |
| 事件过期 | 30 天后标记 decayed |
| 触发词过期 | 关联事件全 decayed 后移除 |

**事务安全核心：** `add_risk_event_with_baseline_update()` 在单 SQLite 事务中完成：

```sql
BEGIN TRANSACTION
  INSERT INTO risk_events (...) VALUES (...)
  SELECT * FROM risk_events WHERE user_id=? AND decayed=0
  INSERT OR REPLACE INTO risk_baselines (...) VALUES (...)
COMMIT
```

利用 SQLite 串行化写事务，即使 10 个并发请求也不会丢失事件。

**读取规则（`RiskMemoryReader.get_baseline()`）：**
1. 优先读取 `risk_baselines` 表 + `risk_triggers` 表
2. 旧 JSON `risk_memory` 作为 fallback（回滚兼容，Phase 2 可移除）
3. 返回格式不变（兼容 agent_orchestrator.py 零修改）

**SessionRiskAggregator Safety Gate（规则 5）：**

```
baseline = "high" 且 session_level < level_1 → 提升至 level_1
baseline = "medium" 且 当前轮和上轮不都是 level_0 → 提升至 level_1
```

返回值新增 `baseline_applied` 审计字段，记录实际使用的基线。

### 3.6 推荐反馈子系统

- `recommendation_events` 表 — 记录每次推荐的类型和条目
- `recommendation_feedback` 表 — 记录用户对具体内容的反馈（accepted/rejected）
- 反馈摘要注入到提示词的"用户长期画像"部分
- RecommendGate 使用反馈数据调整推荐策略

### 3.7 统一记忆写入 Pipeline（Phase 2）

**MemoryWriter** (`memory_writer.py`) 是 Phase 2 新增的长期记忆写入入口，在 `ConversationManager.add_interaction()` 末尾触发。

**写入流程：**

```
每轮对话结束
  ↓
MemoryCandidateExtractor.extract(TurnContext)
  ├─ _extract_stress_source()     — stress_source 候选
  ├─ _extract_preferences()       — support_preference / avoid_preference 候选
  └─ _extract_mood_event()        — 高强度情绪事件候选
  ↓
MemoryPolicy.should_write()       — 按类型分策略门控
  ↓
MemoryPolicy.assign_importance()  — 多因子评分（风险/强度/显式/重复）
MemoryPolicy.assign_confidence()  — 按来源分级（explicit 0.9 → inferred 0.6）
MemoryPolicy.assign_ttl()         — 按类型分配 TTL
  ↓
MemoryStore.batch_write()         — 事务写入 memory_items
```

**写入门控规则：**

| 候选类型 | 写入条件 | 重要性 | 置信度 | TTL |
|---------|---------|--------|--------|-----|
| `stress_source` | 出现 ≥2 次（not yet strict） | 0.70 + 风险加分 | 0.50-0.90 | 180 天 |
| `support_preference` | confidence ≥ 0.75 或 source=explicit | 0.95（explicit） | 0.90（explicit） | 长期 |
| `avoid_preference` | 同上 | 0.95（explicit） | 0.90（explicit） | 长期 |
| `mood_event` | intensity ≥ 0.65 或 risk ≥ level_1 | 0.45-0.60 | 0.50-0.80 | 90 天 |

**MemoryStore 升级（Phase 2）：**
- 惰性建表：支持 `:memory:` 模式独立使用
- `busy_timeout=5000`：高并发写入不报 locked
- `access_count` / `last_accessed_at` 自动追踪：get/search 时更新
- `:memory:` 模式下复用连接，文件模式下每操作新连接

## 5. 持久化策略

### 5.1 数据库表结构

**原有表（7 张）：**

| 表名 | 主键/索引 | 数据量预期 | 清理策略 |
|------|----------|-----------|---------|
| sessions | (user_id, session_id) UNIQUE | 按活跃用户 | 30 天 TTL |
| conversation_history | (session_id) FK | 每会话 ~20-200 轮 | 级联删除随 sessions |
| emotion_timeline | (session_id) FK | 每会话 ~20-200 条 | 同上 |
| user_profile | (user_id) PK | 每用户一条 | 无 TTL |
| mood_events | (user_id, created_at) | 无上限 | **无 TTL** |
| recommendation_events | (session_id) FK | 每会话 ~5-20 条 | 级联删除 |
| recommendation_feedback | (session_id, content_id) UNIQUE | 每会话 ~5-20 条 | 级联删除 |

**v2.0 新增表（7 张）：**

| 表名 | 主键/索引 | 用途 | 清理策略 |
|------|----------|------|---------|
| memory_items | (id) PK | 统一长期记忆存储（含 importance / confidence / TTL） | TTL 衰减 → archived |
| memory_embeddings | (memory_id) FK | 向量 embedding 存储 | 随 memory_items 级联 |
| risk_events | (id) PK + (user_id, event_time) | append-only 风险事件日志 | 30 天标记 decayed |
| risk_baselines | (user_id) PK | 每用户一行风险基线 | 随事件更新 |
| risk_triggers | (user_id, trigger) UNIQUE | 触发词频次统计 | 30 天不活跃标记 decayed |
| protective_factors | (id) PK | 保护因素 | 无 TTL |
| memory_outbox | (id) PK | 异步任务队列（embedding / consolidation） | 消费后清理 |

### 5.2 读写路径

```
读取路径（每次请求）:
  ConversationManager.get_or_create_session_async()
    → 查内存 sessions dict (命中率 ≈ 连续请求时高)
    → 未命中 → AsyncDatabaseManager.get_session_data()
      → 4 次 SQL 查询 (sessions + history + emotion + recommendation)
    → 填充内存 dict

  RiskMemoryReader.get_baseline()        ← v2.0: 从 risk_baselines 表
    → risk_memory_store.get_baseline()   ← 主读取路径
    → (fallback: user_profile JSON)      ← 回滚兼容

  UserProfileTool.get_profile()
    → 读取 user_profile.preferences

  MoodTrackingTool.get_recent_trend()
    → 读取 mood_events 最近记录

写入路径（每轮交互）:
  ConversationManager.add_interaction()
    → 同步写入内存 (即时生效)
    → _schedule_persistence() → 异步 Task 包含 4 个写入:
      1. add_conversation_turn()        → conversation_history
      2. add_emotion_event()            → emotion_timeline
      3. create_or_update_session()     → sessions
      4. add_mood_event()               → mood_events
      + upsert_user_profile()           → user_profile

  RiskMemoryWriter.update()             ← v2.0: 主写入 RiskMemoryStore
    → risk_memory_store.add_risk_event_with_baseline_update()  ← 单事务
    → risk_memory_store.add_risk_trigger()
    → (兼容写入: user_profile JSON 摘要) ← 可回滚

  MemoryWriter.process_turn()           ← Phase 2: 统一记忆写入
    → MemoryCandidateExtractor.extract()
    → MemoryPolicy.should_write() / assign_importance() / assign_ttl()
    → MemoryStore.batch_write() → memory_items
```

### 5.3 连接管理

| 管理器 | 连接策略 | 用途 |
|--------|---------|------|
| `DatabaseManager` | 5 连接池 + threading.Lock | 同步管理/调试操作 |
| `AsyncDatabaseManager` | 无池，每次操作 open/close | 生产路径 |
| `RiskMemoryStore._get_conn()` | `:memory:` 复用连接 / 文件 DB 新连接 + busy_timeout=5000 | 风险记忆独立存储 |

## 6. 安全与门控机制

### 6.1 Safety Gate（session_risk_aggregator.py 规则 5）

长期风险基线影响当前会话判断：

```
baseline = "high" 且 session_level < level_1 → 提升至 level_1
baseline = "medium" 且 当前轮和上轮不都是 level_0 → 提升至 level_1
```

返回值增加 `baseline_applied` 字段，标识实际使用的基线值。

### 6.2 风险记忆写入门控

```
只有当: risk_level_index(level) >= 2
    且: risk_context.subject != "third_party"
    且: risk_context.subject != "discussion"
才写入风险记忆（写入 risk_events + risk_baselines + risk_triggers 表）
```

### 6.3 画像更新门控

```
压力源: 同一来源最近 6 轮中出现 ≥2 次
支持风格: 显式关键词匹配, 或意图推断 ≥2 次
```

### P0 — 影响正确性

| # | 问题 | 说明 | 建议 |
|---|------|------|------|
| 2 | **异步写入无原子性** | add_interaction() 产生 4 个独立 Task，任一失败其他已写入，无回滚机制 | 包在单个事务中，或使用 outbox 模式 |

### P1 — 影响体验/能力

| # | 问题 | 说明 | 建议 |

### P2 — 影响可维护性

| # | 问题 | 说明 | 建议 |
|---|------|------|------|
| 7 | **无 TTL 的数据无限增长** | mood_events / user_profile 无清理策略 | 设上限或滚动窗口（Phase 4） |
| 8 | **emotion_cache 未长期维护** | sessions[key]['emotion_cache'] 初始化后不再更新，但结构保留 | 清理或实际维护 |

### P3 — 可优化项

| # | 问题 | 说明 | 建议 |
|---|------|------|------|
| 9 | **压缩为规则截断而非 LLM 摘要** | 当前压缩拼接片段，语义丢失；LLM 摘要可保留更多信息但成本高 | 作为可选项评估 |
| 10 | **短时/长时边界模糊** | long_term_profile 同时做缓存和持久化，被逐出后无法区分"本会话学到"与"跨会话已知" | 引入版本号或分两层存储 |
| 11 | **Token 估算回退不准** | tiktoken 不可用时用 len//4，中文偏差大 | 固定使用 tiktoken 并预初始化 |
