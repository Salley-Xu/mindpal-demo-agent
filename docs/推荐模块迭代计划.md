# 推荐模块迭代计划

> 版本: v4.4 → v5.0 | 最后更新: 2026-07-07

---

## 现状

推荐模块已完成功能闭环：门控（RecommendGate）→ 检索（BM25 + 同义词向量 RRF 融合）→ 排序（12 维规则）→ AI Rerank（可选）→ 安全过滤。内容库已从 8 条扩展到 27 条，覆盖 12 种情绪类型，测试覆盖 117 条。

当前模块的核心矛盾不是「能不能推荐」，而是 **「什么时候推荐合适、推荐什么有用、用户是否接受」**——这需要从功能构建转向可观测、可评估、可调优。

---

## 总体路线

```
v4.3 (当前)          v4.4               v4.5               v4.6               v4.7               v5.0
功能闭环         可观测性         门控校准          内容库增强        反馈循环          学习排序
│                │                 │                 │                 │                 │
├── 门控         ├── Trace 日志    ├── 阈值 Grid     ├── 80-120 条      ├── 前端交互      ├── 特征工程
├── 检索         ├── 评测数据集    ├── 冷却细化      ├── 标签体系扩展   ├── 偏好学习      ├── 排序模型
├── 排序         ├── 指标基线      ├── 拒绝信号      ├── 数据质量分     ├── 画像自动更新  ├── 规则+模型融合
├── 安全过滤     └── 数据库增强    └── hard/soft 调优 └── embedding 接入  └── 效果统计      └── A/B 测试
└── 117 测试
```

**核心原则**：
1. **可观测先于可调优** — 没有 trace 和评测集之前，不凭感觉调参
2. **安全不可妥协** — Level 2/3 的安全指标必须保持 100%
3. **渐进增强** — 每一步都保留回退能力，不一次性推倒重来
4. **数据驱动** — 权重和阈值调优基于评测数据，而非直觉

### 评测基线（v4.4.0）

| 指标 | 值 | 评判 |
|------|-----|------|
| Safety Lock Rate | 100% | ✅ Level 3 全部拦截 |
| Level 2 Filter Rate | 100% | ✅ Level 2 正确过滤 |
| Cooldown Accuracy | 100% | ✅ 冷却机制有效 |
| None Accuracy | 100% | ✅ 不推荐场景正确 |
| Gate Accuracy | 81.25% | 🟡 18/96 门控判断错误 |
| Soft Recall | 68.42% | 🟡 18 条应 soft 的漏推 |

**关键发现**：Hard 阈值 0.58 对意图较强但情绪强度不高的求助场景（如"推荐一些求职准备的资料"，intensity=0.70, intent=seeking_help）过高，计算得分约 0.38，远低于阈值。这是 v4.5 校准的直接依据。

## v4.5（下一步）— 门控校准

### 目标

用评测数据驱动 RecommendGate 阈值和权重调优，将 Gate Accuracy 从 81% 提升到 90%+，并修复 Hard Precision 0% 的问题。

### 具体任务

#### 1. 阈值 Grid Search

```python
soft_thresholds = [0.15, 0.18, 0.20, 0.22, 0.25, 0.28]
hard_thresholds  = [0.40, 0.45, 0.50, 0.55, 0.58, 0.62]
```

对每组组合运行 `eval_recommend_gate.py`，选择 Gate Accuracy + Mode Accuracy 加权最优。

#### 2. Hard 判定逻辑调整

当前问题：intent=seeking_help 但 emotion_intensity<0.8 时 score 不够高。

方案选项：
- **A**（推荐）：降低 hard_threshold 至 0.45-0.50，同时严格意图条件
- **B**：提高 intent_score 映射值 seeking_help 从 0.75→0.85
- **C**：当 intent=seeking_help 时给予 score boost

优先方案 A，保持公式简单。

#### 3. 用户拒绝推荐信号

解析用户对话中的拒绝意图（如"不用了""我不需要""上次推荐的没用"），在 `conversation_summary` 中标记 `has_rejected_recommendation`，门控据此降权。

#### 4. 冷却机制细化

- 区分 hard/soft 推荐的冷却惩罚强度
- 冷去惩罚接入配置文件（当前硬编码）

### 交付物

| 产出 | 路径 |
|------|------|
| 校准脚本 | `scripts/tune_recommend_gate.py` |
| 校准报告 | `reports/recommend_gate_calibration.md` |
| 门控逻辑更新 | `backend/recommend_gate.py` |
| 评测集补充 | `agent_test_data/datasets/recommend_gate/recommend_gate.jsonl`（补充拒绝信号用例） |

### 成功标准

- [ ] Gate Accuracy ≥ 90%
- [ ] Mode Accuracy ≥ 80%
- [ ] Hard Precision ≥ 60%
- [ ] Soft Recall ≥ 85%
- [ ] 安全指标保持 100%

### 具体任务

## v4.7 — 用户反馈循环

### 目标

从「系统觉得好」到「用户觉得好」。建立用户反馈采集 → 偏好更新 → 推荐优化的闭环。

### 具体任务

#### 1. 隐式反馈采集

在前端推荐卡片下方增加：
- **有帮助 👍** → 更新 preferred_types / preferred_categories
- **不适合 👎** → 加入 rejected_types / rejected_categories
- **以后推荐 →** 标记内容暂不推荐
- **换一个 ↻** → 当前内容当前会话不再出现

#### 2. 反馈 API

```python
POST /content/feedback
{
    "recommendation_id": "...",
    "item_id": "article_001",
    "feedback_type": "helpful" | "not_helpful" | "dismiss" | "refresh",
    "context": {}  # 当时的情绪/风险状态
}
```

#### 3. 偏好自动更新逻辑

```python
if feedback == "helpful":
    profile.preferred_types += [item.type]
    profile.preferred_categories += [item.category]
    # 衰减窗口内加权

if feedback == "not_helpful":
    profile.rejected_ids += [item.id]
    profile.rejected_categories += [item.category]
    # 30 天后自动衰减
```

#### 4. 推荐效果统计仪表盘

基于 trace 日志产出的关键指标面板：
- 推荐接受率（accept_rate）
- 各类场景推荐分布
- 内容热度排名
- 用户反馈汇总

## v5.0 — 学习排序

### 目标

从纯规则排序进化到「规则 + 学习」融合排序。在积累足够 trace 和反馈数据后，训练一个 lightweight 排序模型（LightGBM / LambdaMART）优化推荐排序。

### 特征工程

复用当前 12 维子分作为特征，新增上下文特征：

```python
features = [
    retrieval_score,
    emotion_match_score,
    keyword_match_score,
    concern_match_score,
    stage_match_score,
    risk_match_score,
    preference_score,
    actionability,
    repetition_penalty,
    dedup_penalty,
    popularity_component,
    priority,
    # 上下文特征
    emotion_intensity,
    risk_level (one-hot),
    intent_score,
    conversation_turn,
    recent_recommendation_count,
    user_accept_rate,
    item_accept_rate,
]
```

### 排序模型

| 模型 | 优势 | 选择 |
|------|------|------|
| Logistic Regression | 可解释性强 | 基线模型 |
| LightGBM | 效率高、特征交互好 | ✅ 首选 |
| LambdaMART | 排序导向优化 | 数据充分时可选 |

### 融合策略

```python
final_score = 0.65 × rule_score + 0.35 × learned_score
```

- `learned_score` 置信度低时自动降低比例
- 规则分支作为安全兜底，`model_confidence < 0.5` 时退回到纯规则
- A/B 测试验证提升后再全量

| 模型推理 | `backend/learned_recommender.py` |
| A/B 测试框架 | `backend/ab_test_framework.py` |
| 模型评估报告 | `reports/recommend_ranker_v1_report.md` |
