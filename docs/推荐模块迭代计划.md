# 推荐模块迭代计划

> 版本: v4.6 → v5.0 | 最后更新: 2026-07-14

---

## 现状

推荐模块已完成功能闭环、可观测性、门控校准、内容库增强四轮迭代。目前 v4.6 状态：

- **可观测**：全链路 trace（JSONL）+ 96 条评测数据集 + 8 项自动化指标
- **门控校准后**：Gate Accuracy 95.83%、Mode Accuracy 95.83%、安全指标 100%
- **内容库**：75 条覆盖 12 种情绪，高风险适配 8 条，Level 2 专用 5 条
- **Dense 检索**：`backend/dense_retriever.py`（bge-small-zh-v1.5），`ENABLE_DENSE_RETRIEVAL` 开关控制
- **测试覆盖**：239 条（v4.3 的 110 → v4.6 的 239），全部通过

核心矛盾已从「能不能推荐」推进到 **「推荐的准确性和个性化」**。

**核心原则**：
1. **可观测先于可调优** — 没有 trace 和评测集之前，不凭感觉调参
2. **安全不可妥协** — Level 2/3 的安全指标必须保持 100%
3. **渐进增强** — 每一步都保留回退能力，不一次性推倒重来
4. **数据驱动** — 权重和阈值调优基于评测数据，而非直觉

## v4.5（已完成）— 门控校准

### 目标

用评测数据驱动 RecommendGate 阈值和权重调优，将 Gate Accuracy 从 81% 提升到 90%+，并修复 Hard Precision 0% 的问题。

### 具体方案

#### 1. 软阈值 0.22 → 0.20

将 soft_threshold 从 0.22 下调至 0.20。与"不推荐"场景最高分 0.09 之间保留 0.11 安全间距。

#### 2. 二级硬阈值策略（核心方案）

**不降低通用 hard_threshold**（保持 0.58 避免 false positive），而是针对 `intent=seeking_help` 新增专用低硬阈值：

```python
help_intent_hard_threshold = 0.38  # 当用户明确求助时，更低门槛触发 hard
```

通用硬阈值条件保持不变，新增一个 OR 分支：`user_intent == "seeking_help" and score >= help_intent_hard_threshold`。

#### 3. 用户拒绝检测

新增 `backend/rejection_detector.py`，通过关键词正则匹配检测用户拒绝意图（"不用了""不需要""没兴趣"等 12 种模式），置信度 ≥ 0.5 时在 `conversation_summary.has_rejected_recommendation` 中标记，门控叠加 -0.25 偏好惩罚。

#### 4. 冷却机制配置化

- 冷却值从硬编码迁移到 `config.py`，支持 `.env` 覆盖
- hard/soft 推荐区分：hard 冷却更强（distance≤1 罚 0.50 vs soft 的 0.35）

### 交付物

| 产出 | 路径 | 状态 |
|------|------|------|
| Grid Search 脚本 | `scripts/tune_recommend_gate.py` | ✅ |
| 校准报告 | `reports/recommend_gate_grid_search_20260714_*.json` | ✅ |
| 门控逻辑更新 | `backend/recommend_gate.py` | ✅ |
| 拒绝检测器 | `backend/rejection_detector.py` | ✅ |
| 拒绝检测测试 | `tests/test_m2_rejection_detector.py`（12 项） | ✅ |

## v4.7（下一步）— 用户反馈循环

### 目标

从「系统觉得好」到「用户觉得好」。建立用户反馈采集 → 偏好更新 → 推荐优化的闭环。

### 具体任务

#### 1. 隐式反馈采集

在前端推荐卡片下方增加：
- **有帮助 👍** → 更新 preferred_types / preferred_categories
- **不适合 👎** → 加入 rejected_types / rejected_categories
- **以后推荐 →** 标记内容暂不推荐
- **换一个 ↻** → 当前内容当前会话不再出现

#### 2. 反馈 API

```python
POST /content/feedback
{
    "recommendation_id": "...",
    "item_id": "article_001",
    "feedback_type": "helpful" | "not_helpful" | "dismiss" | "refresh",
    "context": {}  # 当时的情绪/风险状态
}
```

#### 3. 偏好自动更新逻辑

```python
if feedback == "helpful":
    profile.preferred_types += [item.type]
    profile.preferred_categories += [item.category]
    # 衰减窗口内加权

if feedback == "not_helpful":
    profile.rejected_ids += [item.id]
    profile.rejected_categories += [item.category]
    # 30 天后自动衰减
```

#### 4. 推荐效果统计仪表盘

基于 trace 日志产出的关键指标面板：
- 推荐接受率（accept_rate）
- 各类场景推荐分布
- 内容热度排名
- 用户反馈汇总

### 交付物

| 产出 | 路径 |
|------|------|
| 反馈处理模块 | `backend/recommendation_feedback.py` |
| 偏好更新器 | `backend/profile_preference_updater.py` |
| 反馈 API | `backend/api_endpoints.py`（增强） |
| 效果统计脚本 | `scripts/recommendation_stats.py` |

### 成功标准

- [ ] 反馈数据完整写入数据库

## v5.0 — 学习排序

### 目标

从纯规则排序进化到「规则 + 学习」融合排序。在积累足够 trace 和反馈数据后，训练一个 lightweight 排序模型（LightGBM / LambdaMART）优化推荐排序。

### 特征工程

复用当前 12 维子分作为特征，新增上下文特征：

```python
features = [
    retrieval_score,
    emotion_match_score,
    keyword_match_score,
    concern_match_score,
    stage_match_score,
    risk_match_score,
    preference_score,
    actionability,
    repetition_penalty,
    dedup_penalty,
    popularity_component,
    priority,
    # 上下文特征
    emotion_intensity,
    risk_level (one-hot),
    intent_score,
    conversation_turn,
    recent_recommendation_count,
    user_accept_rate,
    item_accept_rate,
]
```

### 排序模型

| 模型 | 优势 | 选择 |
|------|------|------|
| Logistic Regression | 可解释性强 | 基线模型 |
| LightGBM | 效率高、特征交互好 | ✅ 首选 |
| LambdaMART | 排序导向优化 | 数据充分时可选 |

### 融合策略

```python
final_score = 0.65 × rule_score + 0.35 × learned_score
```

- `learned_score` 置信度低时自动降低比例
- 规则分支作为安全兜底，`model_confidence < 0.5` 时退回到纯规则
- A/B 测试验证提升后再全量

### 交付物

| 产出 | 路径 |
|------|------|
| 训练脚本 | `scripts/train_recommend_ranker.py` |
| 模型推理 | `backend/learned_recommender.py` |
| A/B 测试框架 | `backend/ab_test_framework.py` |
| 模型评估报告 | `reports/recommend_ranker_v1_report.md` |
