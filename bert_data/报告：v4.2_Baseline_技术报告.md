# 压力管理 Agent — 风险语义识别 v3 Baseline 技术报告

> 版本: v4.2（多任务+三级融合推理）  
> 日期: 2026-07-02  
> 模型: MultiTaskBERT (shared BERT backbone + 2 heads)  
> 预训练: hfl/chinese-macbert-base  
> 任务: cssrs_lite_level 四分类（0/1/2/3）

---

## 1. 概述

本报告记录了压力管理 Agent 风险语义识别模块的 v3 Baseline 构建过程。项目从公开数据集获取、标签体系设计、数据处理流水线、模型训练到错误分析，完成了完整的闭环。

### 1.1 核心结论

- **最终模型在测试集上达到 Weighted F1=0.60, Macro F1=0.60**
- **规则兜底 + binary 融合 + 四分类三级推理**
- **level_2 召回从 0.45 提升到 0.61**（多任务辅助头贡献）
- **t2→p0 完全漏报从 9 条降到 6 条**（-33%）
- **高风险（level_3）召回 0.75**，规则兜底覆盖短文本高危漏报
- **规则兜底和辅助头均未引入误报**

### 2.5 关键修复记录

| 版本 | 修复内容 | 效果 |
|---|---|---|
| v1 原始 | 关键词规则过度升级 | fine_0~3 被错误升级到 level_3 |
| v2 修复标签 | refine_level_from_tags 信任 SOS-1K 原始标签 | level_0 从 17.7%→28.9% |
| v3 规则兜底 | 短文本高危 pattern + 数据补充 | level_3 训练样本 120→151 |
| v4 最终 | fine_6+ 禁止降级 + 第三方模式修复 | level_3 recall 44%→85% |
| **v4.2 多任务+融合** | 增加 high_risk_binary 头 + 三级推理 | t2→p0 从 9→6, level_2 F1 从 0.55→0.65 |

#### 2.5.1 修复 A：refine_level_from_tags 过度升级

**问题**：关键词规则检测到"今天"、"离开"、"走"等词后，将 SOS-1K fine_3（强烈生存痛苦，无自杀愿望）错误升级到 level_3。

**修复**：修改优先级逻辑：

```python
# 优先级 0：fine_6+（已含计划/方法）禁止被降级
if fine_level >= 6:
    if subject_context == "negated":
        return 0
    return cssrs_level  
```

#### 2.5.2 修复 B：第三方模式误触发

**问题**：`THIRD_PARTY_PATTERNS` 中 "男[友朋]" 无自杀关键词约束，"男朋友" 出现在本人风险表达中（如"我男朋友"）导致整条被标记为第三方并降级到 level_0。

**修复**：模式改为 `(男[友朋]|女[友朋]|亲戚|邻居).*(自杀|跳|割|上吊|离开|想不开)`

## 3. 模型架构

### 3.1 MultiTaskBERT

v4.2 采用多任务架构，共享 BERT backbone，两个独立分类头：

```
输入文本 → BERT backbone (shared)
                ├── classifier_4 → 4分类 (cssrs_lite_level 0-3)
                └── classifier_2 → 二分类 (high_risk_binary: 0=level_0/1, 1=level_2/3)
```

- **主任务**：4 分类交叉熵损失（权重 1.0）
- **辅助任务**：二分类交叉熵损失（权重 0.3）
- **辅助任务目标**：让共享 backbone 学到"是否含风险"这个信号，防止 t2/t3 被压到 level_0/1

### 3.2 训练配置

| 参数 | 值 |
|---|---|
| 架构 | MultiTaskBERT |
| 预训练模型 | hfl/chinese-macbert-base |
| 批次大小 | 16 |
| 学习率 | 2e-5 |
| Epochs | 6 |
| 最大序列长度 | 128 |
| 优化器 | AdamW |
| 学习率调度 | linear warmup (10%) |
| 主任务损失权重 | 1.0 |
| 辅助任务损失权重 | 0.3 |
| 类别权重 | level_0=0.85, level_1=0.93, level_2=0.77, level_3=1.44 |
| GPU | NVIDIA RTX 5070 Laptop (8GB) |

### 3.3 训练过程

```
Epoch 1: Train Loss=1.56  Dev Macro F1=0.42  Dev Binary Acc=0.74
Epoch 2: Train Loss=1.26  Dev Macro F1=0.55  Dev Binary Acc=0.79
Epoch 3: Train Loss=0.98  Dev Macro F1=0.62  Dev Binary Acc=0.83
Epoch 4: Train Loss=0.71  Dev Macro F1=0.64  Dev Binary Acc=0.83

```

最优模型来自 Epoch 5（Dev Macro F1=0.64, Binary F1=0.82）。

### 3.4 规则系统

25 个短文本高危 pattern，在推理时作为第一优先级：

- 进行式自伤："割腕中"、"正在割腕"、"刚割完"
- 重复自伤："第三次割腕"、"又割腕"
- 组合方法："安眠药+酒+跳楼"
- 即刻行动："现在就去死"、"马上就去跳"
- 告别+行动："拜拜啦走饭"、"再见世界"
- 约死+方法："约烧炭"、"一起跳楼"

## 4. 推理系统

### 4.1 三级融合推理

```
输入文本
  ↓
BERT backbone 推理 → logits_4 + logits_2
  ↓
第一级：强规则
  if rule_match(text):
      risk_gate_level = 3
  ↓
第二级：binary 融合
  elif binary_prob > threshold AND pred_4 < 2:
      risk_gate_level = 2
  ↓
第三级：4分类兜底
  else:
      risk_gate_level = pred_4
```

### 4.2 Binary 阈值校准

阈值在 Dev 集上通过目标搜索校准（目标 = -t2→p0 - 0.5×t0→p3 - 0.5×t3_fn）：

| 阈值 | t2→p0 | t0→p3 | t3_fn | 分数 |
|---|---|---|---|---|
| 0.44 | 5 | 4 | 6 | -10.0 |
| **0.50** | **5** | **4** | **6** | **-10.0** ← 选 |
| 0.56 | 5 | 4 | 6 | -10.0 |

最终阈值定为 **0.50**（多个阈值下 Dev 表现一致，选默认值）。

### 4.3 推理优先级总结

| 优先级 | 条件 | 输出 |
|---|---|---|
| P0 | 规则命中 | level_3 |
| P1 | binary_prob > 0.50 AND 4分类 < 2 | level_2 |
| P2 | 4分类预测 | 原值 |

## 8. 限制与后续方向

### 8.1 当前限制

| 限制 | 影响 | 根因 |
|---|---|---|
| 数据量少（1,254 条） | 模型泛化能力受限 | 公开数据重叠度高 |
| 6 条 t2→p0 仍未修复 | 部分中等风险被漏判 | 隐晦表达数据不足 |
| t0→p3 误报增加（4→7） | 增加人工复审量 | multi-task 使 binary 更敏感 |
| 仅单文本分类 | 无法利用上下文 | 当前设计局限 |

### 8.2 建议后续方向

| 方向 | 预期收益 | 工作量 |
|---|---|---|
| 定向补 level_2 短文本隐晦表达 | 修复剩余 6 条 t2→p0 | 低（构造 20-30 条） |
| 并入项目已有数据 | 总数据量 2,000+，提升泛化 | 中 |
| t0→p3 后处理规则（含保护因素时降级） | 减少 3-4 条误报 | 低 |
| 多轮上下文建模 | 理解"想死但不会"vs"我真的要死" | 高（架构改动） |
