# 风险语义识别公开数据与标签处理方案

## 1. 文档目的

本文档用于指导压力管理 Agent 的风险语义识别模块如何获取公开数据、理解数据内容、重构标签体系，并把公开数据和项目已有数据处理成可用于 BERT / MacBERT 训练的数据集。

当前项目已经完成了从数据接入、LLM 预标注、silver/review 分流到 baseline 训练的闭环。多轮实验说明，继续在旧的 `semantic_level_hint` 上调参收益有限，核心问题更可能是旧标签把主体、严重度、手段、紧迫性、求助和保护因素混在了同一个 level 中。因此，后续数据处理的核心目标不是简单扩大数据量，而是把公开数据和已有数据统一迁移到新的、更正交的标签体系中。

本文档重点回答四个问题：

1. 数据从哪里来；
2. 每个数据源大概是什么、适合做什么；
3. 新标签体系应该如何定义；
4. 数据应该如何清洗、映射、复核、切分和沉淀。

---

## 2. 总体结论

现阶段不建议继续寻找一个“完全符合我们标签体系”的公开数据集，因为基本不存在能够直接提供 `subject_context + cssrs_lite_level + evidence_tags + risk_gate_level` 全套标签的数据。

更现实的方案是：

1. 以中文公开数据集作为主数据来源；
2. 参考 C-SSRS 的严重度主轴重新定义标签；
3. 把公开数据中的高低风险、细粒度风险、意图、方法、紧迫性等信息映射为项目自己的标签；
4. 对边界样本做人工复核；
5. 用统一 schema 重新切分 train/dev/test；
6. 用新标签训练 v3 baseline。

推荐主线是：

| 优先级 | 数据源 | 用途 |
|---|---|---|
| P0 | SOS-1K / FineGrainedSuicideDetection | 主数据源，用于严重度分级和 evidence tags 迁移 |
| P0 | SOS-HL-1K | 用于 risk / non-risk 高召回筛查器 |
| P1 | MentalGLM / C-IMHI | 用于解释生成、辅助标注、review 排序 |
| P2 | CLPsych / eRisk | 主要作为标签体系和多轮风险累积思路参考 |
| P2 | C-SSRS | 作为严重度标签设计依据，不作为训练数据 |

---

## 3. 数据获取方式

### 3.1 SOS-1K / FineGrainedSuicideDetection

这是当前最推荐优先使用的数据源。它来自中文社交媒体，面向细粒度自杀风险分类，和项目中的中文压力管理 Agent 风险识别场景最接近。

获取方式：

1. 打开 GitHub 仓库：HongzhiQ/FineGrainedSuicideDetection；
2. 通过 GitHub 页面下载 ZIP，或使用 Git 拉取仓库；
3. 下载后重点查看 `suicideDataProcessing` 目录；
4. 其中 `data` 目录下通常包含二分类数据和细粒度分类数据；
5. 仓库中还包含 LLM 辅助标注、数据增强和模型训练相关材料。

建议重点关注的内容：

| 目录或文件 | 作用 |
|---|---|
| suicideDataProcessing/data/binary | 高低风险二分类数据，可用于训练筛查器 |
| suicideDataProcessing/data/fine-grained | 细粒度风险数据，可用于迁移严重度标签 |
| suicideDataProcessing/LLMs auxiliary annotation | 可参考其 LLM 辅助标注方式 |
| suicideDataProcessing/data augmentation | 可参考其类别不平衡补样策略 |
| ModelTrain | 可参考其 baseline 训练方式，但不需要照搬 |

在本项目中的使用方式：

1. 二分类数据用于 Stage 1 风险筛查；
2. 细粒度数据用于 Stage 2 严重度分级；
3. 数据中的意图、手段、紧迫性信息用于构造 evidence tags；
4. 不建议直接照搬其原始细粒度标签作为最终训练标签，而应该迁移到项目自定义的 `cssrs_lite_level`。

---

### 3.2 SOS-HL-1K / SupervisedVsLLM-EfficacyEval

SOS-HL-1K 是一个中文社交媒体高低自杀风险分类数据集，适合用来训练高召回的风险筛查器。

获取方式：

1. 打开 GitHub 仓库：HongzhiQ/SupervisedVsLLM-EfficacyEval；
2. 下载 ZIP 或拉取仓库；
3. 根据仓库 README 查找 suicide risk classification 相关数据目录；
4. 同时可以查看 supervised learning、few-shot、fine-tuning 等实验目录。

数据说明：

1. 数据来自中文社交媒体；
2. 任务是高风险 / 低风险二分类；
3. 公开说明中提到 SOS-HL-1K 包含 1,249 条帖子；
4. MentalGLM README 中给出的划分为 749 / 250 / 250；
5. 标注方式为人工标注。

在本项目中的使用方式：

1. 适合作为 Stage 1 筛查器训练集；
2. 不适合作为 `cssrs_lite_level` 四分类的直接训练集；
3. 可以与项目已有 level_0、非风险、否定表达、第三方求助样本合并，用于提升 risk / non-risk 区分能力；
4. 对于其中高风险样本，可以再用 LLM 或人工补标 `cssrs_lite_level` 和 `evidence_tags`。

---

### 3.3 MentalGLM / C-IMHI

MentalGLM 是中文社交媒体心理健康分析方向的解释型大模型项目，包含 C-IMHI 数据集、专家示例、指令数据和评估代码。

获取方式：

1. 打开 GitHub 仓库：zwzzzQAQ/MentalGLM；
2. 下载 ZIP 或拉取仓库；
3. 重点查看 `Instruct data`、`Raw data` 和 `Expert_example` 目录；
4. 同时阅读 README 中对 C-IMHI、专家质量检查和模型用途的说明。

数据说明：

1. C-IMHI 是中文社交媒体可解释心理健康指令数据集；
2. 数据形式更接近“输入文本 + 任务指令 + 输出标签 + 决策解释”；
3. 它不是专门为本项目的 BERT 四分类标签设计的；
4. 它更适合作为解释、预标注和质量检查参考。

在本项目中的使用方式：

1. 不建议直接把 C-IMHI 作为 `cssrs_lite_level` 的主训练集；
2. 可以用它学习“如何生成标签解释”和“如何抽取证据”；
3. 可以作为 LLM 预标注 prompt 的参考；
4. 可以辅助 review 样本排序；
5. 可以用于构造或筛选边界样本。

---

### 3.4 C-SSRS

C-SSRS 不是训练数据集，而是自杀风险评估中非常重要的结构化量表。它适合用来定义项目的严重度主轴。

获取方式：

1. 从 Columbia Lighthouse Project 或公开 PDF 获取 C-SSRS 表格和评分说明；
2. 重点阅读 suicidal ideation 部分；
3. 关注 “wish to be dead”、“active suicidal thoughts”、“method”、“intent”、“plan”等递进关系；
4. 不需要把原始问卷当训练样本使用。

在本项目中的使用方式：

1. 用作 `cssrs_lite_level` 标签设计依据；
2. 帮助区分被动死亡愿望、主动自杀想法、方法、意图和计划；
3. 帮助避免把多个语义轴混进同一个标签；
4. 作为标注规范的理论支撑。

---

### 3.5 CLPsych / eRisk

CLPsych 和 eRisk 主要是英文 NLP 风险识别研究中的任务资源。它们可以提供 no / low / moderate / severe 风险分层、多帖子用户级风险识别和早期风险检测思路。

在本项目中的使用方式：

1. 主要作为研究参考；
2. 不建议作为中文 BERT baseline 的主训练数据；
3. 可以借鉴它们对用户级风险、多轮上下文和风险累积的处理方式；
4. 可以作为后续多轮风险门控设计的参考。

---

## 4. 数据源优先级和使用策略

### 4.1 主数据源

主数据源建议使用 SOS-1K / FineGrainedSuicideDetection。

原因是：

1. 中文数据；
2. 社交媒体表达；
3. 与自杀风险直接相关；
4. 同时包含高低风险和细粒度风险信息；
5. 与项目中“隐晦风险表达识别”的需求比较接近。

主要用途：

1. 构建 `cssrs_lite_level`；
2. 构建 `evidence_tags`；
3. 提供 level_2 / level_3 相关高价值样本；
4. 支撑 v3 baseline 训练。

### 4.2 辅助数据源

辅助数据源建议使用 SOS-HL-1K 和 C-IMHI。

SOS-HL-1K 主要用于：

1. risk / non-risk 筛查；
2. 高召回预筛；
3. 二阶段模型的第一阶段训练。

C-IMHI 主要用于：

1. 解释生成；
2. LLM 预标注；
3. 证据抽取；
4. review 样本排序。

### 4.3 项目已有数据

项目已有数据仍然有价值，但不建议直接沿用旧 `semantic_level_hint` 作为核心监督标签。

建议处理方式：

1. 保留原始文本和原始标签；
2. 使用自动迁移规则生成初版 `cssrs_lite_level`；
3. 将不确定样本放入 review 池；
4. 对 review 样本优先复核；
5. 将复核后的样本作为 gold 或 high-quality silver。

## 5. 新标签体系说明

新标签体系应该拆成四层：

1. `subject_context`：说明风险主体和语境；
2. `cssrs_lite_level`：说明本人当前风险严重度；
3. `evidence_tags`：说明判定依据；
4. `risk_gate_level`：系统最终门控等级，由模型、规则和上下文共同推导。

其中，BERT / MacBERT 的核心训练目标应该是 `cssrs_lite_level`，而不是最终的 `risk_gate_level`。

---

## 6. subject_context 标签说明

`subject_context` 用于解决“这句话到底是不是用户本人当前风险”的问题。

建议取值如下：

| 标签 | 含义 | 处理原则 |
|---|---|---|
| self_current | 用户本人当前风险 | 可以进入严重度分级 |
| self_past | 用户本人过去经历 | 不直接等同当前风险，需要结合上下文 |
| third_party | 第三方求助或描述他人风险 | 不直接作为本人风险，但仍需安全回应 |
| negated | 明确否定风险 | 通常不进入高风险严重度 |
| hypothetical | 假设、讨论、科普、引用、影视内容 | 通常不作为本人当前风险 |
| unclear | 主体不明 | 进入 review 或由上下文判断 |

这个字段必须和严重度标签拆开，否则模型会把“第三方求助”和“本人高风险”混在一起。

---

## 7. cssrs_lite_level 标签说明

`cssrs_lite_level` 是新的核心严重度主轴。它参考 C-SSRS 的递进逻辑，但做了工程化简化，适合当前数据量和 BERT 四分类任务。

建议使用 0–3 四级。

| 标签 | 定义 | 说明 |
|---|---|---|
| level_0 | 无本人当前自杀/自伤风险 | 包括普通压力、负面情绪、第三方、否定、讨论、引用等 |
| level_1 | 被动死亡/消失愿望，低行动意图 | 表达“不想存在”“想消失”等，但没有明确主动自杀/自伤想法 |
| level_2 | 明确自杀/自伤想法，但没有计划、准备、紧迫性或明确行动意图 | 已经从被动愿望升级到主动风险意念 |
| level_3 | 出现方法、计划、准备行为、时间紧迫性、明确行动意图或正在实施信号 | 需要最高优先级安全门控 |

### 7.1 level_0

适用情况：

1. 普通压力、焦虑、失眠、低落；
2. 明确说自己没有自伤或自杀想法；
3. 询问第三方情况；
4. 新闻、影视、论文、科普、假设讨论；
5. 情绪负面但没有本人当前风险信号。

注意：

1. 第三方求助不等于本人风险；
2. 否定表达不能因为出现高危词就误判为高风险；
3. 普通崩溃表达不一定等于 level_1 或 level_2。

### 7.2 level_1

适用情况：

1. 被动死亡愿望；
2. 想消失、想不醒来、觉得不存在会更好；
3. 明显绝望但没有主动自伤/自杀意图；
4. 有求助或保护性因素冲突的低意图表达。

核心边界：

level_1 和 level_2 的区别在于：

1. level_1 是“希望不存在”或“被动消失”；
2. level_2 是“明确想到自伤或自杀”。

### 7.3 level_2

适用情况：

1. 明确表达自杀或自伤想法；
2. 但没有具体方法；
3. 没有具体计划；
4. 没有明确近期时间；
5. 没有准备行为；
6. 没有明确行动意图。

核心边界：

level_2 和 level_3 的区别在于：

1. level_2 有明确风险意念；
2. level_3 进一步出现方法、计划、准备、紧迫性或行动意图。

### 7.4 level_3

适用情况：

1. 有方法或手段线索；
2. 有计划或步骤；
3. 有准备行为；
4. 有明确行动意图；
5. 有近期或即时紧迫性；
6. 表达正在实施或即将实施；
7. 表达明显失控且可能伤害自己或他人。

注意：

1. level_3 是 safety gate 的强触发信号；
2. 即使文本中也有求助意图，只要出现强高危信号，仍应保持高风险处理；
3. 保护性因素只能辅助判断，不能覆盖明确高危信号。

---

## 8. evidence_tags 标签说明

`evidence_tags` 是多标签字段，用于说明为什么判成某个 level。

建议标签如下：

| tag | 含义 |
|---|---|
| passive_death_wish | 被动死亡、消失、不想醒来等愿望 |
| active_ideation | 明确自伤或自杀想法 |
| method_signal | 出现方法或手段相关线索 |
| intent_signal | 出现行动意图 |
| plan_signal | 出现计划或步骤 |
| urgency_signal | 出现时间紧迫性 |
| preparation_signal | 出现准备行为 |
| loss_of_control | 表达失控或担心自己失控 |
| help_seeking | 明确求助 |
| protective_factor | 出现保护因素，例如愿意联系他人、仍有顾虑等 |
| negation | 明确否定自伤/自杀风险 |
| third_party | 第三方风险或替他人求助 |
| discussion_context | 科普、讨论、引用、影视、论文语境 |
| severe_distress | 严重痛苦、崩溃、无助，但不一定有自伤/自杀意念 |

这个字段的价值在于：

1. 提升模型可解释性；
2. 支撑多任务训练；
3. 帮助错误分析；
4. 参与最终安全门控；
5. 支持 review 样本排序。

---

## 9. risk_gate_level 说明

`risk_gate_level` 是 Agent 系统最终使用的门控等级，不建议作为第一阶段 BERT 的主训练标签。

原因是：

1. 它不只取决于文本语义；
2. 它还取决于规则命中、上下文惯性、用户历史状态、保护因素和当前对话场景；
3. 如果直接把它作为文本分类标签，会再次把多个语义轴混在一起。

建议定义：

| 门控等级 | 含义 | 系统策略 |
|---|---|---|
| gate_0 | 普通对话 | 正常支持和推荐 |
| gate_1 | 需要谨慎支持 | 使用低认知负担建议，适度安全确认 |
| gate_2 | 高风险支持 | 限制普通推荐，优先安全确认和求助引导 |
| gate_3 | 危机响应 | 关闭普通推荐，进入危机支持流程 |

`risk_gate_level` 应由以下信息融合得到：

1. BERT 输出的 `cssrs_lite_level`；
2. `subject_context`；
3. `evidence_tags`；
4. 规则层高危信号；
5. 最近几轮上下文；
6. 历史 risk state；
7. 保护因素和求助意愿。

## 10. 公开数据到新标签的映射策略

### 10.1 SOS-HL-1K 映射策略

SOS-HL-1K 是高低风险二分类数据，不应该直接映射成四级严重度。

建议：

| 原始信息 | 项目使用方式 |
|---|---|
| low risk | 用于 risk / non-risk 筛查；部分可进入 level_0 或 level_1 |
| high risk | 用于 risk / non-risk 筛查；需要二次标注为 level_1 / 2 / 3 |

处理原则：

1. low risk 不等于一定是 level_0；
2. high risk 不等于一定是 level_3；
3. 高低风险标签只能作为粗筛信号；
4. 需要结合文本证据重新标注 `cssrs_lite_level`。

---

### 10.2 SOS-1K 细粒度数据映射策略

SOS-1K 的细粒度风险标签可以作为迁移基础，但不能直接照搬。

建议流程：

1. 先读取原始文本和原始风险标签；
2. 根据原始风险分数或等级做粗分桶；
3. 再根据文本中是否出现被动死亡愿望、主动意念、方法、意图、计划、紧迫性等证据进行校验；
4. 生成初版 `cssrs_lite_level`；
5. 对所有边界样本进入 review。

映射原则：

| 证据情况 | 建议目标标签 |
|---|---|
| 无本人当前风险、第三方、否定、讨论 | level_0 |
| 被动死亡或消失愿望，无明确主动意念 | level_1 |
| 明确主动自伤/自杀想法，但无方法、计划、准备、紧迫性 | level_2 |
| 出现方法、计划、准备、紧迫性、行动意图或正在实施信号 | level_3 |

注意：

1. 原始分数只能辅助，不能替代文本证据；
2. 如果分数和证据冲突，以证据为主；
3. 出现方法、计划、准备、紧迫性时，应优先进入 level_3 或 review；
4. 表达严重痛苦但没有自伤/自杀意念时，不应直接升到 level_2。

---

### 10.3 C-IMHI 映射策略

C-IMHI 更适合作为解释型辅助数据，不建议直接转为主分类训练集。

建议使用方式：

1. 从 C-IMHI 中抽取 suicide risk detection 相关样本；
2. 使用其中的解释内容辅助生成 `evidence_tags`；
3. 用于训练或评估解释生成模块；
4. 用于 review 样本排序；
5. 不直接把其指令输出作为 `cssrs_lite_level` gold 标签。

---

## 11. 数据处理流程

### 11.1 第一步：建立原始数据区

所有公开数据下载后，首先进入 raw 区域。

原则：

1. raw 数据只读；
2. 不直接在 raw 文件上修改；
3. 保留数据来源、下载时间、仓库版本或 commit 信息；
4. 每个数据源单独建目录；
5. 记录 license、引用方式和使用限制。

建议记录字段：

| 字段 | 说明 |
|---|---|
| source_name | 数据源名称 |
| source_url | 数据来源链接 |
| download_date | 下载日期 |
| original_file | 原始文件名 |
| license_note | 许可或使用限制说明 |
| citation | 推荐引用 |

---

### 11.2 第二步：统一样本 schema

所有数据源都应转成统一 schema。

建议字段：

| 字段 | 说明 |
|---|---|
| sample_id | 项目内部样本 ID |
| source | 数据来源 |
| raw_id | 原始数据 ID |
| text | 清洗后的文本 |
| raw_text | 原始文本，可选 |
| subject_context | 主体与语境标签 |
| cssrs_lite_level | 核心严重度标签 |
| evidence_tags | 多标签证据 |
| original_label | 原始标签 |
| label_quality | gold / silver / review |
| mapping_method | human / rule / llm / mixed |
| review_reason | 进入 review 的原因 |
| group_id | 用于去重和 group-safe split |

---

### 11.3 第三步：文本清洗

文本清洗目标不是把文本“改得干净”，而是让模型看到稳定输入，同时保留风险语义。

建议保留：

1. 情绪词；
2. 否定词；
3. 时间词；
4. 求助表达；
5. 第一人称和第三人称信息；
6. 标点中的强情绪信号。

建议处理：

1. URL 统一替换为占位符；
2. 用户名、手机号、地址等隐私信息脱敏；
3. 重复空格和异常控制字符清理；
4. 表情符号可以保留或转为统一占位符；
5. 繁简体根据项目语言统一；
6. 过短、无语义、纯转发文本进入低优先级队列。

不建议处理：

1. 不要删除否定词；
2. 不要删除时间词；
3. 不要删除第一人称或第三人称代词；
4. 不要过度改写原文；
5. 不要用摘要替代原始训练文本。

---

### 11.4 第四步：去重与近重复处理

风险语义数据很容易出现重复或模板化表达。去重非常重要，否则 train/dev 泄漏会让指标虚高。

建议处理：

1. 完全相同文本去重；
2. 清洗后相同文本去重；
3. 高相似文本归为同一个 group；
4. LLM 增强样本和原始样本归为同一个 group；
5. 同一原始帖子衍生出的多个样本不得分到不同集合。

输出：

1. 去重后数据集；
2. 重复样本报告；
3. group_id 映射表。

---

### 11.5 第五步：初始标签映射

对公开数据进行自动映射，生成初版标签。

映射顺序：

1. 先判断 `subject_context`；
2. 再判断 `evidence_tags`；
3. 再根据证据生成 `cssrs_lite_level`；
4. 最后判断是否进入 review。

进入 review 的典型情况：

1. 主体不明；
2. 否定表达但包含高危词；
3. 第三方求助但语境复杂；
4. 被动消失和主动意念边界不清；
5. 主动意念和有计划/意图边界不清；
6. 有保护因素但同时有高危信号；
7. 原始标签和规则映射冲突；
8. LLM 标注和规则标注冲突。

---

### 11.6 第六步：silver/review 分流

自动映射后的数据不应全部直接进入训练集。

建议分为三类：

| 类型 | 含义 | 用法 |
|---|---|---|
| gold | 人工确认过的高质量标签 | 优先进入 train/dev/test |
| silver | 规则或 LLM 高置信标签 | 可进入训练，但要控制比例 |
| review | 不确定或边界样本 | 暂不进入训练，优先人工复核 |

silver 样本进入训练前需要满足：

1. 主体明确；
2. 证据和 level 一致；
3. 不涉及复杂否定；
4. 不涉及明显主体混淆；
5. 不存在原始标签与迁移标签强冲突。

review 样本优先级建议：

1. level_2 / level_3 边界；
2. level_1 / level_2 边界；
3. 第三方 vs 本人风险；
4. 否定表达；
5. 有保护因素但表达危险；
6. 模型历史上容易错判的类型。

---

### 11.7 第七步：人工复核

人工复核不是重新标全量数据，而是优先处理最影响模型边界的样本。

复核时应该同时确认：

1. `subject_context` 是否正确；
2. `cssrs_lite_level` 是否符合定义；
3. `evidence_tags` 是否覆盖主要证据；
4. 是否需要加入 hard cases；
5. 是否需要更新标注规范。

复核原则：

1. 严重度主轴只看本人当前风险；
2. 第三方和否定表达单独标，不混入高风险本人标签；
3. 只要出现明确方法、计划、准备、紧迫性或行动意图，必须进入高优先级复核；
4. 保护因素不能覆盖明确高危信号；
5. 情绪痛苦不等于自杀风险，需要区分 severe distress 和 suicidal ideation。

---

### 11.8 第八步：训练集切分

重新切分时不能只做随机切分。

建议使用：

1. group-safe split；
2. label stratified split；
3. hard-case dev set；
4. 固定 test set。

dev 集应包含：

1. 普通样本；
2. level_1 / level_2 边界样本；
3. level_2 / level_3 边界样本；
4. 第三方求助样本；
5. 否定表达样本；
6. 讨论、引用、假设语境样本；
7. 有保护因素但有风险表达的样本。

test 集原则：

1. 尽量只放 gold 或人工复核过的 high-quality silver；
2. 不放 LLM 生成的增强样本；
3. 不与 train/dev 有近重复；
4. 保持每个 level 都有足够样本；
5. 单独记录边界样本子集指标。

## 13. 质量检查清单

数据进入训练前，至少检查以下内容：

### 13.1 标签分布

需要检查：

1. 每个 `cssrs_lite_level` 的样本数；
2. 每个 `subject_context` 的样本数；
3. 每个 `evidence_tags` 的样本数；
4. level_2 和 level_3 是否过少；
5. level_0 是否过度占比。

### 13.2 标签一致性

需要检查：

1. level_0 是否错误包含 active_ideation；
2. level_3 是否缺少高危 evidence tag；
3. third_party 是否被标成本人高风险；
4. negation 是否被误标为高风险；
5. method / plan / urgency 是否和 level 不一致。

### 13.3 数据泄漏

需要检查：

1. train/dev/test 是否有完全重复文本；
2. 是否有近重复文本跨集合；
3. LLM 增强样本是否和原始样本跨集合；
4. 同一原始样本衍生数据是否跨集合。

### 13.4 难例覆盖

需要检查 dev/test 是否覆盖：

1. 被动消失；
2. 主动意念；
3. 高危紧迫性；
4. 第三方求助；
5. 否定表达；
6. 讨论语境；
7. 保护因素冲突；
8. 严重痛苦但无自杀意念。

## 14. 建议的项目推进顺序

当前最合理的推进顺序是：

1. 获取 SOS-1K / FineGrainedSuicideDetection；
2. 获取 SOS-HL-1K / SupervisedVsLLM-EfficacyEval；
3. 可选获取 MentalGLM / C-IMHI；
4. 建立 raw 数据目录并记录来源；
5. 把所有数据转成统一 schema；
6. 按新标签体系进行初始映射；
7. 将不确定样本进入 review；
8. 优先复核 level_1/2、level_2/3、第三方、否定表达样本；
9. 固化 `cssrs_lite_level` 标注规范；
10. 重新切分 train/dev/test；
11. 训练 v3 baseline；
12. 基于错误分析继续定向补样。

不建议路线：

1. 不建议继续在旧 `semantic_level_hint` 上大规模调参；
2. 不建议直接把 SOS-1K 的原始分数当作最终标签；
3. 不建议把 high / low 风险二分类直接扩展成四分类；
4. 不建议把 C-IMHI 直接当作 BERT 分类主训练集；
5. 不建议在没有人工复核边界样本前继续堆普通 silver 数据。

## 15. 面试或项目汇报表述

可以这样说明：

本项目的数据构建不是简单下载公开数据后直接训练，而是先对公开数据进行任务适配。我们优先选择中文社交媒体自杀风险数据集，例如 SOS-1K 和 SOS-HL-1K，因为它们与压力管理 Agent 中的中文风险表达场景最接近。其中，SOS-HL-1K 适合训练 risk / non-risk 筛查器，SOS-1K 的细粒度风险信息适合迁移到新的严重度标签。

在标签体系上，我们没有继续沿用旧的 `semantic_level_hint`，因为它混入了主体、严重度、计划、紧迫性和保护因素等多个维度。新的设计参考 C-SSRS 的严重度递进逻辑，将标签拆成 `subject_context`、`cssrs_lite_level` 和 `evidence_tags`。其中，`cssrs_lite_level` 是 BERT 的核心监督目标，负责表示本人当前风险严重度；`evidence_tags` 用来提供可解释证据；最终的 `risk_gate_level` 则由模型输出、规则层和上下文风险惯性共同决定。

数据处理上，我们会把公开数据和已有数据统一转成标准 schema，先做自动映射，再用 silver/review 机制分流。对于 level_1/2、level_2/3、第三方求助、否定表达等边界样本，优先进入人工复核。最后使用 group-safe 的方式重新切分 train/dev/test，确保 dev/test 能覆盖真正影响风险识别能力的难例。

---

## 16. 一句话总结

当前项目的数据路线应该从“继续扩大旧标签训练集”切换为“基于公开中文风险数据，参考 C-SSRS 重构严重度标签，并通过统一 schema、自动迁移、人工复核和 group-safe 切分，构建适合 v3 baseline 的高质量训练集”。
